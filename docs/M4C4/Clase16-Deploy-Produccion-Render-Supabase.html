01 · Punto de partida

Funciona, pero todavía nadie puede entrar

CampusFlow ya tiene arquitectura modular, usuarios, JWT, pagos y suscripciones. El límite es físico: todo vive en la máquina de cada estudiante.

Decide antes de desplegar

Si CampusFlow funciona en localhost, ¿qué le falta para convertirse en un producto que otra persona pueda usar?

Piensa en dirección pública, ejecución continua, datos y secretos.

Ver respuesta

Necesita un servidor público, una base accesible desde ese servidor y configuración segura fuera del código.

Desplegar es poner la aplicación en un servidor de internet. Al final tendrá una URL como https://campusflow.onrender.com, PostgreSQL en la nube y pagos de prueba funcionando sin depender del computador local.

03 · Decisión arquitectónica

La base cambia; el dominio no

En local CampusFlow conserva MySQL. En producción usa PostgreSQL. JPA permite que las entidades sigan intactas.

Predice · 30 segundos

Al pasar de MySQL a PostgreSQL, ¿qué esperarías modificar: las entidades, los servicios o la conexión?

Recupera para qué sirven JPA e Hibernate.

Comprobar razonamiento

La conexión y el driver. JPA mantiene el modelo de entidades; Hibernate genera el SQL apropiado para la base conectada.

Permanece igual

  • Entidades y relaciones JPA
  • Servicios y reglas de negocio
  • Controllers y endpoints
  • MySQL para el trabajo local

Cambia en producción

  • Driver PostgreSQL disponible
  • URL, usuario y contraseña
  • Puerto entregado por Render
  • Webhook público en vez de Stripe CLI
J

Primera idea central

JPA desacopla el modelo de una base concreta: una misma aplicación puede trabajar localmente con MySQL y en producción con PostgreSQL.

04 · Preparación

Spring debe hablar Postgres y obedecer el puerto

Son dos inserciones pequeñas. No se elimina el driver MySQL ni se fija un puerto exclusivo para la nube.

01

Agregar el traductor de PostgreSQL

Edita campusflow/pom.xml y agrega esta dependencia dentro de <dependencies>, sin quitar la de MySQL. Spring Boot administra la versión.

Editarcampusflow/pom.xml · XML
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <scope>runtime</scope>
</dependency>
02

Aceptar el puerto del entorno

Edita src/main/resources/application.properties. Si existe PORT, Spring lo usa; si no, conserva 8080 para local.

Editarsrc/main/resources/application.properties · properties
server.port=${PORT:8080}
Checkpoint

Recarga Maven y vuelve a ejecutar en local

CampusFlow debe seguir iniciando con MySQL en localhost:8080. Estos cambios amplían las opciones de ejecución; no reemplazan el entorno local.

05 · Empaque y entrega

Docker construye la maleta; GitHub la pone al alcance

El Dockerfile compila el proyecto en una etapa y ejecuta solo el .jar en una imagen final más liviana.

Detecta la decisión

¿Por qué conviene separar la compilación y la ejecución en dos etapas?

Ver criterio

Maven solo hace falta para construir. La imagen final necesita Java y el .jar, por eso puede ser más pequeña y simple.

Ver Dockerfile completo Crear · campusflow/Dockerfile · Dockerfile · listo para copiar
Crearcampusflow/Dockerfile
# Etapa 1: construir el .jar con Maven
FROM maven:3.9-eclipse-temurin-17 AS build
WORKDIR /app
COPY . .
RUN mvn clean package -DskipTests

# Etapa 2: imagen liviana solo para correr el .jar
FROM eclipse-temurin:17-jre
WORKDIR /app
COPY --from=build /app/target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
Ejecutarterminal · dentro de campusflow/
git add .
git commit -m "Preparar CampusFlow para deploy: driver Postgres, puerto y Dockerfile"
git push
!

No publiques la llave sk_test_

Antes del git push, evita dejar secretos en application.properties. La guía propone ignorar ese archivo o rotar la llave de prueba al terminar. En Render, los secretos vivirán como variables de entorno.

06 · Datos en la nube

Supabase: crear Postgres y elegir la conexión correcta

La decisión crítica no es solo crear la base: Render necesita la conexión Session pooler.

1

Nuevo proyecto

Entra a supabase.com, crea campusflow y elige una región cercana, por ejemplo East US.

2

Contraseña

Define y guarda la contraseña de la base. No se mostrará completa otra vez.

3

Espera

La creación puede tomar 1–2 minutos. Hibernate creará las tablas al arrancar.

4

Connect

Abre Connect y selecciona Session pooler.

Anticipa el fallo

¿Qué ocurrirá si copias la conexión directa de Supabase porque parece la opción más simple?

La conexión directa usa IPv6; el camino de Render necesita IPv4.

Comprobar

El deploy puede fallar con could not connect. Usa el host del pooler, reconocible por pooler.supabase.com:5432.

Datos que debes copiar del Session pooler
CampoForma esperadaUso
Hostaws-0-us-east-1.pooler.supabase.comServidor PostgreSQL accesible por IPv4.
Port5432Puerto de PostgreSQL.
DatabasepostgresBase creada por Supabase.
Userpostgres.<id-del-proyecto>Usuario específico del pooler.
PasswordLa guardada al crear el proyectoCredencial secreta.

07 · Configuración externa

Los secretos viven en Render, no en GitHub

Las variables del servidor reemplazan la configuración equivalente al ejecutar en producción; local puede conservar MySQL.

i

Segunda idea central

Una imagen puede viajar entre entornos. Lo que cambia es la configuración que el entorno le entrega al arrancar.

PrepararValores JDBC desde Supabase Session pooler
SPRING_DATASOURCE_URL       = jdbc:postgresql://aws-0-<region>.pooler.supabase.com:5432/postgres?sslmode=require
SPRING_DATASOURCE_USERNAME  = postgres.<id-de-tu-proyecto>
SPRING_DATASOURCE_PASSWORD  = <la-contraseña-del-proyecto>
Render · EnvironmentVariables requeridas para CampusFlow
SPRING_DATASOURCE_URL        = (la URL JDBC preparada arriba)
SPRING_DATASOURCE_USERNAME   = (el usuario del pooler)
SPRING_DATASOURCE_PASSWORD   = (la contraseña de Supabase)

STRIPE_SECRET_KEY            = sk_test_...
STRIPE_PRICE_PAGO_UNICO      = price_...
STRIPE_PRICE_PLAN_INDIVIDUAL = price_...
STRIPE_WEBHOOK_SECRET        = whsec_PENDIENTE
sslmode=require

Obliga a cifrar la conexión con Supabase.

Tres valores separados

Evitan problemas con contraseñas que contienen caracteres especiales.

whsec_PENDIENTE

Es temporal; se reemplaza cuando Stripe conozca la URL pública.

09 · Stripe en producción

El webhook ya no necesita un puente local

Stripe puede llamar directamente a Render. El código de WebhookService no cambia; cambia el endpoint registrado y su secreto.

Compara

En local usabas stripe listen. ¿Qué reemplaza ese puente cuando la app ya tiene una URL pública?

Ver respuesta

Un endpoint registrado en el Dashboard de Stripe: https://TU-APP.onrender.com/api/pagos/webhook.

1

Webhooks

En Stripe Sandbox abre dashboard.stripe.com/webhooks y crea un destino de eventos.

2

Your account

Selecciona eventos de tu propia cuenta.

3

Evento

Marca checkout.session.completed.

4

Endpoint

Elige Webhook endpoint y pega la ruta pública completa.

5

Signing secret

Revela y copia el nuevo whsec_....

EndpointStripe · Webhook público
https://TU-APP.onrender.com/api/pagos/webhook
✓

Cierra el círculo

En Render → Environment, reemplaza whsec_PENDIENTE por el secreto del endpoint registrado. Al guardar, Render vuelve a desplegar automáticamente.

Dos pausas del nivel gratuito

Render duerme la app tras 15 minutos sin uso. Supabase puede pausar el proyecto tras aproximadamente una semana sin actividad y permite reactivarlo desde el panel.

Dominio personalizado: útil, pero opcional

La URL onrender.com ya es pública y suficiente para el portafolio. Un dominio como campusflow.com requiere comprarlo y configurarlo en Render → Settings → Custom Domains mediante los registros DNS indicados.

13 · Evidencia profesional

“Está en producción” significa diez sí verificables

No basta con que el dashboard diga “deployed”. El producto debe responder, persistir y completar su regla de negocio.

  • GitHub contiene el Dockerfile y el driver de PostgreSQL.
  • Supabase tiene la base PostgreSQL y conservaste su contraseña.
  • Render entrega una URL pública que responde.
  • SPRING_DATASOURCE_* apunta al Session pooler.
  • Las variables de Stripe están en Render, no en el código público.
  • Stripe tiene el webhook de Render y Render tiene su whsec_.
  • GET /api/cursos responde desde la URL pública.
  • Registro y login funcionan; el usuario aparece en Supabase.
  • Un pago de prueba deja la suscripción en estado ACTIVA.
  • Render Logs y Stripe Event deliveries muestran un flujo sano.

14 · Cierre del módulo

CampusFlow ya no es una promesa local

El módulo termina con un backend SaaS público, persistente y capaz de completar un pago de prueba de punta a punta.

Cierre · piensa antes de revelar

El código no cambió al pasar de MySQL a PostgreSQL ni de localhost a internet. ¿Qué decisiones anteriores hicieron eso posible?

Ver respuesta

No fue una sola tecnología: fue una arquitectura diseñada para cambiar sin romperse.

JPA abstrae la base, las capas y dominios separan responsabilidades, la configuración entra por propiedades y variables, y servicios especializados se encargan de pagos, datos y ejecución. Pensar como ingeniero es tomar decisiones que permiten crecer y cambiar sin reescribirlo todo.
