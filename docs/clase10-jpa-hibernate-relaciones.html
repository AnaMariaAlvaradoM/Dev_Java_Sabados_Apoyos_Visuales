01
Modelo mental

Persistir cambia las reglas del catálogo

La aplicación deja de depender de una lista temporal. Java describe el modelo; Hibernate traduce ese modelo a SQL y MySQL conserva los datos.

Problema de negocio

Si el dueño cargó 200 productos ayer, ¿por qué tendría que volver a crearlos después de reiniciar el servidor?

Estándar

JPA

Define cómo una clase Java se corresponde con una tabla. Es el contrato que usamos al programar.

Motor

Hibernate

Implementa ese contrato: genera SQL, lo ejecuta y reconstruye objetos con los resultados.

Destino

MySQL

Guarda filas, relaciones y llaves para que la información permanezca entre ejecuciones.

Antes: memoria

  • List<Producto> vive dentro del proceso.
  • Reiniciar borra el catálogo.
  • El service administra datos temporales.

Ahora: persistencia

  • JpaRepository habla con MySQL.
  • Reiniciar no elimina las filas.
  • El modelo Java guía la estructura.
Criterio profesional

Programa contra JPA, no contra detalles del motor

JPA es el estándar estable; Hibernate es una implementación. Esa separación reduce el acoplamiento y mantiene abierta la posibilidad de cambiar de proveedor.

Muestra y formatea el SQL generado para aprender de él.

Convertir Producto en entidad y ubicar las llaves foráneas

Edita: src/main/java/com/devsenior/gestorproductos/model/Producto.java. Conserva los getters y setters de todos los campos.

EDITARsrc/main/java/com/devsenior/gestorproductos/model/Producto.java
package com.devsenior.gestorproductos.model;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.JoinColumn;
import jakarta.persistence.ManyToOne;

@Entity
public class Producto {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String nombre;
    private String descripcion;
    private double precio;
    private int stock;

    @ManyToOne
    @JoinColumn(name = "categoria_id")
    private Categoria categoria;

    @ManyToOne
    @JoinColumn(name = "marca_id")
    private Marca marca;

    public Producto() {}

    // getters y setters de todos los campos
}
@Entity

Clase → tabla

Incluye la clase en el modelo persistente que Hibernate inspeccionará al iniciar.

@Id + IDENTITY

Llave autogenerada

MySQL asigna el identificador como un AUTO_INCREMENT.

@JoinColumn

FK con nombre explícito

La llave foránea vive en producto, el lado dueño de la relación.

Decisión de diseño

mappedBy = "categoria" señala al dueño real

El texto debe coincidir exactamente con el campo categoria de Producto. No modeles ambos sentidos por simetría: hazlo solo cuando la navegación inversa aporte valor.

  • Las tres clases tienen constructor vacío y acceso a sus campos.
  • Producto usa Long como id.
  • Categoria conoce sus productos; Marca no mantiene una lista innecesaria.

Capa de datos

El repository sustituye el SQL repetitivo

Una interfaz describe la entidad y el tipo de su llave. Spring genera la implementación, ofrece operaciones CRUD y convierte nombres de método en consultas.

Controller

Recibe HTTP y delega.

Service

Repository

Expresa operaciones de persistencia.

Guarda y consulta filas.

Checkpoint 06

Reemplazar la lista en memoria

Edita: src/main/java/com/devsenior/gestorproductos/service/ProductoService.java. La inyección por constructor entrega los tres repositorios.

EDITARservice/ProductoService.java · núcleo de persistencia
@Service
public class ProductoService {
    private final ProductoRepository productoRepository;
    private final CategoriaRepository categoriaRepository;
    private final MarcaRepository marcaRepository;

    public ProductoService(ProductoRepository productoRepository,
                           CategoriaRepository categoriaRepository,
                           MarcaRepository marcaRepository) {
        this.productoRepository = productoRepository;
        this.categoriaRepository = categoriaRepository;
        this.marcaRepository = marcaRepository;
    }

    public List<Producto> listarProductos() {
        return productoRepository.findAll();
    }

    public List<Producto> listarPorCategoria(Long categoriaId) {
        return productoRepository.findByCategoriaId(categoriaId);
    }

    public Producto agregarProducto(Producto producto) {
        resolverCategoria(producto);
        resolverMarca(producto);
        return productoRepository.save(producto);
    }
}
AÑADIRservice/ProductoService.java · métodos privados
private void resolverCategoria(Producto producto) {
    if (producto.getCategoria() != null
            && producto.getCategoria().getId() != null) {
        Categoria categoria = categoriaRepository
                .findById(producto.getCategoria().getId())
                .orElse(null);
        producto.setCategoria(categoria);
    }
}

private void resolverMarca(Producto producto) {
    if (producto.getMarca() != null
            && producto.getMarca().getId() != null) {
        Marca marca = marcaRepository
                .findById(producto.getMarca().getId())
                .orElse(null);
        producto.setMarca(marca);
    }
}
Observa la decisión

El JSON trae referencias, no entidades completas

Antes de guardar, el service convierte cada id en una entidad recuperada de la base. Así Hibernate puede construir llaves foráneas válidas.

EDITARcontroller/ProductoController.java · versión inicial
@RestController
@RequestMapping("/api/productos")
public class ProductoController {
    private final ProductoService productoService;

    public ProductoController(ProductoService productoService) {
        this.productoService = productoService;
    }

    @GetMapping
    public List<Producto> obtenerProductos() {
        return productoService.listarProductos();
    }

    @GetMapping("/categoria/{categoriaId}")
    public List<Producto> obtenerPorCategoria(
            @PathVariable Long categoriaId) {
        return productoService.listarPorCategoria(categoriaId);
    }

    @PostMapping
    public Producto crearProducto(@RequestBody Producto producto) {
        return productoService.agregarProducto(producto);
    }
}

07
Debugging intencional

El dato está bien; la respuesta está mal diseñada

Una relación bidireccional puede convertirse en un espejo infinito cuando Jackson intenta serializar entidades completas.

Experimento

Abre GET /api/productos. ¿Por qué categoria vuelve a contener productos una y otra vez?

Producto
incluye →
Categoria
↑ cada producto vuelve a incluirla
Lista de productos
← incluye
Categoria
Síntoma

HttpMessageNotWritableException

El mensaje sobre profundidad de anidamiento no acusa a MySQL. Indica que la conversión a JSON siguió el ciclo Producto → Categoria → productos → Categoria… hasta alcanzar el límite.

Entidad expuesta

  • Refleja relaciones internas.
  • Puede recorrer ciclos.
  • Acopla la API a la base.
  • Expone campos sin intención.

Respuesta diseñada

  • Contiene solo datos útiles.
  • Usa valores planos.
  • No revela la estructura interna.
  • Puede evolucionar con el cliente.
Diagnóstico

Separa persistencia de representación

Las entidades modelan la conversación con la base. La API necesita su propio contrato de salida: un DTO.

08
Contrato de salida

El DTO corta el ciclo y decide qué se expone

En lugar de anidar entidades, el DTO transforma categoría y marca en textos. El controller recibe una entidad para guardar, pero devuelve una representación segura.

Checkpoint 08

Crear ProductoDTO

Crea: src/main/java/com/devsenior/gestorproductos/dto/ProductoDTO.java. Genera getters para todos sus campos.

CREARdto/ProductoDTO.java
package com.devsenior.gestorproductos.dto;

import com.devsenior.gestorproductos.model.Producto;

public class ProductoDTO {
    private Long id;
    private String nombre;
    private double precio;
    private int stock;
    private String categoria;
    private String marca;

    public ProductoDTO(Producto producto) {
        this.id = producto.getId();
        this.nombre = producto.getNombre();
        this.precio = producto.getPrecio();
        this.stock = producto.getStock();
        this.categoria = producto.getCategoria() != null
                ? producto.getCategoria().getNombre() : null;
        this.marca = producto.getMarca() != null
                ? producto.getMarca().getNombre() : null;
    }

    // getters de todos los campos
}
Checkpoint 09

Transformar antes de responder

Edita: controller/ProductoController.java e importa ProductoDTO. Los tres endpoints devuelven DTOs.

EDITARcontroller/ProductoController.java · respuestas
@GetMapping
public List<ProductoDTO> obtenerProductos() {
    return productoService.listarProductos()
            .stream()
            .map(ProductoDTO::new)
            .toList();
}

@GetMapping("/categoria/{categoriaId}")
public List<ProductoDTO> obtenerPorCategoria(
        @PathVariable Long categoriaId) {
    return productoService.listarPorCategoria(categoriaId)
            .stream()
            .map(ProductoDTO::new)
            .toList();
}

@PostMapping
public ProductoDTO crearProducto(@RequestBody Producto producto) {
    Producto guardado = productoService.agregarProducto(producto);
    return new ProductoDTO(guardado);
}

Regla de la API

Entrada y salida pueden ser distintas

El POST recibe Producto porque necesita las referencias para guardar. Devuelve ProductoDTO porque el cliente necesita una respuesta plana y estable.

Siguiente aplicación

CategoriaDTO usa la misma estrategia

Crea un DTO con id y nombre. En CategoriaController, transforma el GET con .stream().map(CategoriaDTO::new).toList() y el POST con new CategoriaDTO(...).

@JsonIgnore

  • Corta la serialización.
  • Resuelve el síntoma rápido.
  • No diseña un contrato de salida.

DTO

  • Elige campos deliberadamente.
  • Oculta detalles internos.
  • Evita ciclos y protege la evolución de la API.
  • GET /api/productos devuelve una lista finita.
  • Categoría y marca aparecen como texto.
  • Ningún endpoint de producto devuelve la entidad directamente.
  • GET /api/categorias también usa su DTO.
